Comment ça marche

Une règle est une donnée (un fichier JSON), pas un programme. Le même moteur lit toutes les règles, à chaque événement choisi dans la règle.

flowchart LR
  A[Dossier du patient] --> P((SAFE))
  R[Règles si… alors] --> P
  P --> O[Ordonnances pré-remplies]
  P --> V[Alertes de prévention]
  P --> E[Échéances de suivi]

Les règles chargées

Trois origines. Les cas sourcés citent la page officielle lue et listent ce qui n'est pas encodé.

À trancher ensuite

  1. Dépistage colorectal. Le document dit 50 à 75 ans, la page officielle lue dit 50 à 74 ans.
  2. Périodicité saisie pour un patient. Prime-t-elle sur la règle quand elle est plus longue ?
  3. Lithium. Le RCP demande des contrôles « réguliers » sans fréquence chiffrée : à fixer par le médecin.
  4. Rappel dTcaP. Fenêtre de temps pour « vaccin fait » et rattrapage après l'âge fixe.
  5. Écriture des règles. Qui peut les créer, les modifier et les activer ?
SAFE : Si · Alors · Faire · Échéance. Le moteur lit les règles, le générateur les écrit. Démo générée à partir du dépôt du projet.
